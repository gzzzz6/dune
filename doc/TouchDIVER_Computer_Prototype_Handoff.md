# TouchDIVER 电脑端原型交接任务书

## 目标

在没有机械臂和潜航器的条件下，用电脑键盘模拟手部操作输入，控制 DUNE 中的虚拟舵机，并验证从输入、IMC 通信、DUNE 控制任务到模拟执行器的链路。实现要保留输入适配边界，使以后可以将键盘输入替换为 WEART TouchDIVER Pro SDK 输入。

首版不接真实手套 SDK、不实现机械臂逆运动学，也不修改 IMC 消息定义。触觉反馈只用合成接触数据验证命令生成，不宣称验证真实触感或力反馈。

## 当前仓库事实

- 工作区是 WSL，仓库根目录 `/home/dev/dune/dune`，构建目录 `/home/dev/dune/build`。
- `run_sim_with_neptus.sh` 启动 `lauv-simulator-1` 仿真和 Neptus。
- [`src/Simulators/Servos/Task.cpp`](../src/Simulators/Servos/Task.cpp) 的舵机模拟器有四个通道，消费 `SetServoPosition` 并发布 `ServoPosition`。`Maximum Angle` 限制舵机位置，开启限速时依靠 `SimulatedState` 周期更新位置。
- [`etc/auv/simulator.ini`](../etc/auv/simulator.ini) 启用该模拟器，最大角度配置为 45 度。
- [`etc/auv/transports.ini`](../etc/auv/transports.ini) 的 UDP 消息表包含 `SetServoPosition` 和 `ServoPosition`，但 `SetServoPosition` 的 UDP 速率限制为 1 Hz，不适合作为连续操纵输入。
- `RemoteActions` 是现有周期遥操作输入，`Control/AUV/RemoteOperation` 和 `Control/ROV/RemoteOperation` 已展示它的解析模式。IMC tuple list 的数值约定是轴值约为 `-127..127`。
- `dune-sendmsg` 可以发单条 `SetServoPosition` 或 `RemoteActions`，但不应由控制循环高频启动子进程。
- 当前仓库没有 WEART SDK、手套桥接程序，也没有机械臂模型。

## 固定实现决策

- 采用混合结构：电脑端独立 Python 程序产生键盘输入并发送 IMC `RemoteActions`；DUNE C++ Task 接收输入、处理使能/超时/限幅，并输出 `SetServoPosition` 到虚拟舵机模拟器。
- Python 端直接编码和发送 IMC v5 UDP 报文，禁止在周期循环中调用 `dune-sendmsg` 子进程。实现前先验证本地 DUNE 使用的 IMC 协议版本和 UDP 端口；目标为本机 `127.0.0.1:6002`。
- 键盘端使用终端非阻塞按键读取，默认最多控制两路通道以模拟夹爪的开合；输入扩展为四路，但初始映射只启用 0、1 号通道。按键方案：`a/z` 增减通道 0，`s/x` 增减通道 1，`0` 归零，`e` 使能/停用，`q` 安全退出。按下 `e` 前不发送非零输入。
- 键盘值归一化为 `-127..127`，按 10 Hz 周期发送 `RemoteActions`，消息包含固定命名轴 `Grip0`、`Grip1` 及 `Enable`、`Stop` 状态。具体 tuple-list 文本必须和 DUNE Task 解析字段保持一致。
- DUNE 任务将轴值映射到舵机角度，默认最大幅度 30 度，额外夹紧在模拟器配置的 ±45 度以内；没有新的有效输入超过 500 ms 时，将目标归零并撤销使能。任务每周期都发布目标舵机命令，周期默认 10 Hz。任务默认禁止驱动真实硬件，不得改写 AUV 姿态、速度、深度控制器。
- 任务作为新增、独立的 `Control/Manipulator/Teleoperation` 或等价命名模块；通过配置显式启用，仅在 Simulation profile 中开启。不要把操纵臂逻辑混入 `Control/AUV/Attitude/Task.cpp` 或现有推进器远控任务。
- 稳定输入接口定义为一个可替换的数据源边界：当前 `KeyboardInput` 提供使能状态、各轴 `[-1,1]` 值、单调时间戳和有效性；后续 `WeartInput` 可适配 SDK 数据到同一结构。首版不引入 SDK 依赖。
- 工作区已有未跟踪备份文件，执行 AI 必须原样保留；只提交本任务需要的变更。

## 分阶段执行与验收

### 阶段 0：基线和协议验证

执行 AI 先确认当前构建可用、profile 可加载、IMC schema 的协议版本和 UDP 消息过滤规则。用 `dune-sendmsg` 单次发送 0 号舵机 20 度，确认模拟器收到并产生 `ServoPosition`。若本机默认目的端口与 6002 不符，以配置和运行日志为准，记录最终端口再继续。

**交付物：**记录仿真启动命令、消息端口、IMC 版本、基线发送和反馈证据。

**验收条件：**DUNE 仿真启动无新增错误；单条命令能驱动模拟器；确认 UDP `SetServoPosition` 1 Hz 限速，因此连续输入改走 `RemoteActions`。

### 阶段 1：电脑端键盘输入器

新增独立 Python 输入程序，不依赖手套 SDK。实现非阻塞终端按键、两路轴值调整、使能切换、归零、急停/退出和 10 Hz 周期发送。程序终止、键盘中断或终端恢复时必须在退出前尽力发送零值和停用状态。用配置或命令行指定 DUNE IP/UDP 端口，默认本机地址；向终端显示当前值、连接目标和使能状态。

**交付物：**可运行的 Python 程序、最小运行说明、可重复的 IMC 报文发送/解析检查。

**验收条件：**不安装额外第三方 Python 包即可运行（若协议库确有必要，先提交理由并将依赖锁定）；按键行为可复现；连续发包稳定约 10 Hz；未使能时轴值保持为零；收到 Ctrl+C 后终端回显恢复且发送停止状态。

### 阶段 2：DUNE 控制任务和虚拟舵机链路

新增独立 DUNE 任务，消费 `RemoteActions`，只接受约定字段。将输入归一化值映射到 0、1 号舵机，验证数值和使能状态，丢弃非法值。有效输入超时 500 ms 后输出零目标。通过 `SetServoPosition` 驱动 `Simulators.Servos`，并发布必要的状态日志供验收。仅在 Simulation profile 中配置启用。

**交付物：**DUNE Task、配置变更、构建结果和端到端操作记录。

**验收条件：**DUNE 编译通过；启动仿真后键盘可分别改变两路模拟舵机；角度不会超过设定限制；释放按键后目标保持稳定；断开输入程序/停止发包后 500 ms 内归零；停用时不能产生非零目标；未影响现有 AUV 导航和姿态控制行为。

### 阶段 3：软件闭环、故障场景和交接验收

增加一个合成接触数据源或测试模式，把虚拟接触事件映射成抽象触觉命令，并记录其输出。此阶段只验证触觉命令生成，不需要也不模拟 SDK 内部行为。补齐无效报文、超时、退出、重启和两个输入端同时发包等边界说明；执行 AI 逐项运行验收并提供原始日志或命令输出。

**交付物：**端到端演示步骤、测试证据、数据源适配说明和仍未验证事项。

**验收条件：**从电脑按键到 DUNE 虚拟舵机、从合成接触到抽象触觉命令两条软件路径均可重复；故障时进入零输出/停用状态；报告清楚区分已验证的软件链路与未来需实物验证的追踪精度、触觉效果、机械臂运动学和真实通信时延。

## 验收协作约定

- 每阶段结束先提交变更摘要、测试命令、关键输出和未解决问题，暂停推进后续阶段，等待主控 AI 审核。
- 主控 AI 按该阶段验收条件检查差异、源码边界、构建/运行证据及是否保留用户现有未跟踪文件；通过后才允许进入下一阶段。失败则给出具体缺项并要求执行 AI 修正。
- 最终验收需检查 DUNE 配置默认不启用真实硬件输出、超时能安全归零、所有新增代码符合 DUNE C++98 风格约束，且不修改 IMC schema。

## 最终交付清单

- 键盘输入器及运行说明。
- 新增的 DUNE 虚拟操纵任务和 Simulation 配置。
- 可复现的构建与端到端验收记录。
- 后续替换成 WEART SDK 数据源所需的输入适配说明。

## 未来接入手套时的适配边界

以后由独立 `WeartInput` 实现同一输入数据源接口：通过厂商 Middleware/SDK 收追踪数据，转换出使能、轴值、时间戳和有效性；不要改变 DUNE Task 消费的内部格式。触觉方向另设输出适配器，把未来真实机械臂力/接触传感器生成的抽象触觉事件转换为 SDK 效果。首版不假定 SDK 运行平台、采样率或机器人接触传感器规格。
